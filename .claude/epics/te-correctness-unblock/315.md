# Task: Canvas position-counter visibility

## Description

The portfolio card in the canvas reports "OpenPositions" from the broker (distinct tickers). The risk gate now (post task 002) reports the same denominator. Surface both the distinct-ticker count and the underlying trade-row count so any future drift is immediately visible to the operator.

Minor UI change; large diagnostic value.

## Acceptance Criteria

- [ ] `/api/node/portfolio` response includes both `OpenPositions` (distinct tickers) and `OpenTradeRows` (DB row count, including consolidated rows excluded).
- [ ] `/api/node/risk` response includes both fields too, computed identically.
- [ ] Canvas portfolio card renders `1` when both agree; renders `1 (8 rows)` (or similar) when they diverge.
- [ ] Tooltip / aria-label explains the distinction for accessibility.

## Technical Details

- Backend: `internal/web/handlers.go` — both `handleRisk` and `handlePortfolio`. Compute `OpenTradeRows` from `len(openTrades)`; compute `OpenPositions` from distinct (ticker, direction) pairs (or read from broker for `handlePortfolio`).
- Frontend: `web/frontend/src/components/portfolio/...` — the existing portfolio card component. Conditionally render the parenthetical when values differ.
- After Epic A task 001 + 002 land, the divergence indicator should be hidden in steady state. Its presence indicates either a bug or pending consolidation work.

## Dependencies

- Task 002 (provides the distinct-ticker counting in the gate; this task surfaces it).
