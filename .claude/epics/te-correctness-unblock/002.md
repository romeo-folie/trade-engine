# Task: Distinct-ticker position counting + max_per_ticker cap

## Description

The risk gate currently counts `len(openTrades)` (database rows). It should count distinct `(ticker, direction)` pairs so a single-ticker burst can never exhaust the budget again. Also add a `max_per_ticker` config (default 2) so future bursts can't recur regardless of which gate enforces.

This is the structural fix that makes the JMIA-collapse migration durable. Without this, the next dev-mode restart sequence reproduces the problem.

## Acceptance Criteria

- [ ] `internal/engine/engine.go:1272` counts distinct `(ticker, direction)` pairs from `openTrades`.
- [ ] New config field: `risk.max_per_ticker int` (default `2`). Loaded from yaml; surfaced in TUI config view; updatable at runtime via existing config endpoints.
- [ ] New risk check: `checkMaxPerTicker` in `internal/risk/manager.go`. Block reason: `open positions in %s reach per-ticker limit %d`. Runs after `checkMaxOpenPositions`.
- [ ] `risk.CheckInput` extended with `OpenByTicker map[string]int` (count per ticker for current direction).
- [ ] Engine populates `OpenByTicker` from `openTrades` before constructing `CheckInput`.
- [ ] Unit tests: distinct-counting behaviour (8 JMIA rows = 1 position); per-ticker cap enforcement (existing 2 longs in TICKER + 1 incoming BUY = block).

## Technical Details

- Counting logic:
  ```go
  positions := make(map[string]struct{}, len(openTrades))
  byTicker := make(map[string]int, len(openTrades))
  for _, t := range openTrades {
      key := t.Ticker + "|" + string(t.Direction)
      positions[key] = struct{}{}
      if (action == "BUY" && t.Direction == "long") || (action == "SELL" && t.Direction == "short") {
          byTicker[t.Ticker]++
      }
  }
  // riskIn.OpenPositions = len(positions)
  // riskIn.OpenByTicker  = byTicker
  ```
- The existing `checkMaxOpenPositions` does not change; it still consumes `OpenPositions`. The numerator just becomes correct.
- `checkMaxPerTicker` returns pass when `byTicker[ticker] < cfg.MaxPerTicker`; else fail with the block reason above.
- Default value `2` chosen so legitimate pyramiding (Epic B FR-12) still works.
