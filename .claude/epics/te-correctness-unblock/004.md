# Task: Feedback-loop audit (performanceContext flow)

## Description

The TradingAgents framework (HKUDS) reports compounding gains from injecting recent decisions and cross-ticker lessons into each analysis prompt. This codebase has the infrastructure (`internal/feedback`, `feedback_insights` and `feedback_flags` tables) but it's unverified that the loop actually closes — i.e. that yesterday's outcomes are reaching today's prompt.

Audit-first: check whether `performanceContext` is non-empty for a representative ticker, and whether the analyst sees it. Fix any breakage discovered.

## Acceptance Criteria

- [ ] Audit report committed (PR description or a one-time file under `.claude/epics/te-correctness-unblock/audit-feedback.md`):
  - For at least one ticker with closed trades (e.g. NVDA or IBKR), capture the prompt that gets sent to one analyst at the next analysis tick.
  - Confirm whether `performanceContext` is non-empty in `AnalysisRequest`.
  - Confirm whether the rendered prompt body contains the feedback section.
  - Inspect `feedback_insights` row count and last-write timestamp; record both.
- [ ] If `performanceContext` is empty when it should not be: open a follow-up issue or extend this task to fix.
- [ ] If reaching the request struct but not the rendered prompt: fix the prompt builder to include it.
- [ ] If `feedback_insights` is stale (no recent writes despite trade closures): fix the writer.

## Technical Details

- Entry points to inspect:
  - `internal/feedback.GetPerformanceContext(ctx, ticker) (string, error)`
  - `internal/engine/engine.go` near line 770: `if e.cfg.Feedback.Enabled && e.cfg.Feedback.PromptEnrichment { ... }`
  - The prompt builder paths in `internal/analysis/prompts/stock.go` (`buildUser` consumes `performanceContext`).

  - Add a one-off DEBUG log line that dumps the full prompt for a single ticker, gated by an env var. Run once. Remove the log line in the same PR.
  - Or write a dry-run script under `cmd/` that builds the prompt for a given ticker and prints it.
