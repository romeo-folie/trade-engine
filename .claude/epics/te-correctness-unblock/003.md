# Task: Startup broker-vs-DB reconciler

## Description

On engine boot, fetch broker positions and compare to DB-tracked open trades. Log a WARN per ticker where the two diverge by more than a tolerance threshold. This is observability-first: do not auto-mutate state. Mirrors the visibility-first stance of `reconcileDoneSessionTrades` in PR #297.

Without this, the next time DB-vs-broker drifts, we won't notice until the position budget is silently exhausted again.

## Acceptance Criteria

- [ ] New function `engine.reconcileBrokerVsDB(ctx)` callable from engine startup.
- [ ] Reads broker positions via `brokerView.PositionsSnapshot(ctx)`.
- [ ] Reads DB open trades grouped by ticker via `store.GetOpenTrades`.
- [ ] For each ticker present in either set: compares broker quantity to summed DB quantity.
- [ ] Emits a WARN log line when `|broker_qty - db_qty| > tolerance` (configurable; default 0.01 shares).
- [ ] WARN line includes: ticker, broker_qty, db_qty, db_row_count.
- [ ] If broker is unavailable (`ErrBrokerUnavailable`), logs INFO ("reconciler skipped — broker unavailable") and returns nil — does not crash boot.
- [ ] Called once during engine startup, after `store.Connect` and broker initialization.

## Technical Details

- File: new `internal/engine/reconcile.go` (or extend an existing reconciler file if one already exists).
- Pattern to follow: `reconcileDoneSessionTrades` in the ORB package. Read-only audit, structured WARN with all relevant fields, no automatic state changes.
- Tolerance is for fractional-share trades (Alpaca) where rounding can produce sub-share differences.
- Boot-time call site: wherever `store.Connect` and broker init currently happen (likely `cmd/tradeengine/main.go`).
