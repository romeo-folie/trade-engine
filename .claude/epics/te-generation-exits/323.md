# Task: Specialist analysts (Grok 4.20 lesson)

## Description

Grok 4.20's winning entry in the Alpha Arena stock contest used four role-specialised agents (fundamental / technical / sentiment / risk-manager) debating before deciding. The current arbiter runs N copies of the same prompt across providers — diversity comes from model weights only, not from role specialisation.

Replace the duplicate-prompt ensemble with role-specialised prompts; the arbiter resolves disagreement instead of averaging.

## Acceptance Criteria

- [ ] Four new role prompts in `internal/analysis/prompts/`:
  - `buildFundamentalSystem` — earnings, catalysts, sector context.
  - `buildTechnicalSystem` — indicators, structure, levels (close to today's `buildSystem`).
  - `buildSentimentSystem` — news/social signals, catalyst quality.
  - `buildRiskManagerSystem` — vetoes anything violating portfolio constraints; emphasises risk discipline.
- [ ] Provider-to-role mapping configurable: `analysis.specialist_roles: { fundamental: claude, technical: deepseek, sentiment: gemini, risk_manager: grok }`.
- [ ] Arbiter (`internal/analysis/arbiter`) resolves disagreement: if 3+ roles agree on action, use that. Otherwise, risk-manager's veto is decisive when present.
- [ ] Backwards compatibility: behind a feature flag `analysis.specialist_mode_enabled` (default `false`). When off, the existing ensemble path is unchanged.
- [ ] Tests: each role prompt rendered + asserted to contain its role-specific guidance; arbiter resolution covers 3-of-4 agreement, 2-of-4 split, risk-manager veto.

## Technical Details

- Conflicts with task 002 because both touch `internal/analysis/prompts/stock.go`. Sequence them: 002 first (small prompt tightening), then 007.
- Prompt structure: each role prompt extends the existing JSON output schema. The arbiter must continue to consume the same `AnalysisResult` shape so downstream code is unchanged.
- Risk-manager prompt is the novel one — it should prefer WAIT over BUY when sizing/exposure/correlation concerns are flagged. Effectively a built-in safety circuit.
- Cost note: 4 specialist calls vs N-provider duplicate calls — likely similar token spend, but with much higher information per token.

## Dependencies

- Conflicts with task 002 (both edit `prompts/stock.go`).
