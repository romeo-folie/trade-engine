# Task: Gate calibration — R:R floor + tiered confidence + scanner-RSI loosen

## Description

Three small calibration changes that together unlock most of the BUY-signal volume uplift. All in `internal/risk/manager.go`, default config, and `~/.tradeengine/config.yaml`. Backed by historical signal data: ~30 blocked signals had R:R between 1.40 and 1.49 (right under the current floor); both executed winners cleared at R:R ≥ 1.65, so the floor is the right gate but the cutoff is one notch too tight.

## Acceptance Criteria

- [ ] `risk.min_risk_reward` default lowered from 1.50 → 1.40. Updated in defaults, example yaml, and user yaml.
- [ ] `checkConfidence` replaced with `checkConfidenceTiered`:
  - if R:R ≥ 2.0: require conf ≥ 0.60.
  - if 1.4 ≤ R:R < 2.0: require conf ≥ 0.65.
  - if R:R < 1.4: rejected by `checkRiskReward` already; `checkConfidenceTiered` is a no-op in that band.
- [ ] Tier thresholds expressed as config fields, not magic numbers.
- [ ] Scanner-only RSI loosen: when source == "scanner" AND scanner conviction ≥ 0.75, `rsi_delta_threshold` is reduced to 2.0 for that ticker. Implementation lives near the existing scanner-cooldown reduction at `internal/engine/engine.go:627–636`.
- [ ] Manual watchlist tickers see no change to RSI delta threshold.
- [ ] Block-reason strings updated to reflect tiered logic: e.g. `confidence 0.61 < tier-required 0.65 (R:R 1.50)`.

## Technical Details

- Tiered confidence config:
  ```yaml
  risk:
    min_risk_reward: 1.40
    confidence_tiers:
      - rr_min: 2.0
        conf_min: 0.60
      - rr_min: 1.4
        conf_min: 0.65
  ```
- Scanner RSI loosen pattern mirrors PR #309 (scanner cooldown ÷ 4): a per-source override applied to a copy of `mcCfg` before `CheckMaterialChange`.
- Scanner conviction is already available via the watchlist `min_confidence` field or the in-memory scanner state — confirm and use whichever is canonical.
