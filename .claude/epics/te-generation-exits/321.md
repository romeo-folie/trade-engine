# Task: Multi-timeframe arbiter for borderline WAITs

## Description

Many of the 415 WAIT outcomes since Apr 15 land in the 0.55–0.70 confidence band — borderline, not clearly negative. For these, run a second pass on the alternate timeframe (1H ↔ 4H) and re-arbitrate. Cost: 2× tokens on borderline cases only. Some of those WAITs likely flip to BUY/SELL when seen on a different timeframe.

## Acceptance Criteria

- [ ] After arbiter resolution, if final action is WAIT and confidence is in `[0.55, 0.70]`:
  - Run a second analysis on the alternate timeframe (1H ↔ 4H, configurable).
  - Re-arbitrate combining both timeframe outputs.
  - Final action emerges from the combined arbiter.
- [ ] Tokens for the second pass charged to a distinct cost-tracking bucket so we can measure the marginal cost.
- [ ] Config: `analysis.multi_timeframe_borderline_enabled` (default `true`), `analysis.multi_timeframe_alt_map` (1H → 4H, 4H → 1H, daily → 1H).
- [ ] If the alternate timeframe is unavailable (no candles), fall back to the original WAIT result without crashing.

## Technical Details

- Hook point: after `e.analyzer.AnalyzeFull` returns, in `internal/engine/engine.go` near line 807.
- Reuse the existing arbiter; the second pass produces another `AnalysisResult` and feeds both into a combine step.
- Avoid recursion: the second pass must be flagged so it can't trigger a third.
- Borderline band is configurable but should default to 0.55–0.70 (deliberately narrow — we don't want every WAIT to double up).
