# Task: Server-side trailing stop manager (Claude Alpha Arena lesson)

## Description

Anthropic's Claude entry in Alpha Arena Season 1 (−12%) had the same shape as the current trade engine: long-only, no dynamic stop-loss, missed reversals. The fix is server-side trailing stops — submit/replace a real STOP order with the broker so exits happen on price action regardless of analyst-loop latency.

This is the single biggest exit-discipline upgrade and the biggest task in Epic B.

## Acceptance Criteria

- [ ] New package `internal/execution/trailing` (or extension of an existing exit module) implementing:
  - `Manager.UpdateAll(ctx)` — iterates open long trades, recomputes trailing stop, submits/replaces broker STOP order.
  - Trailing-stop formula: `new_stop = max(current_stop, high_water_mark × (1 − atr_multiple))`.
  - `high_water_mark` per trade tracked in DB (new column `high_water_mark NUMERIC` on `trades`, or in a sidecar table).
  - `atr_multiple` configurable per strategy (default `1.5`).
- [ ] Manager runs on a schedule (e.g. every portfolio-update tick or every 60s, whichever exists) — reuse existing scheduler.
- [ ] Stop order submission via broker abstraction. For Alpaca: submit a STOP order; if one already exists, REPLACE (not cancel+submit) when supported.
- [ ] If broker STOP submission fails: log WARN, retry on next tick, do not crash.
- [ ] Initial scope: stocks/long-only. Forex/ORB exits unchanged.
- [ ] When a trade's stop is hit and the position closes, update DB `trades.status='closed'` and `exit_price` via existing fill-handling code (already in place for non-trailing stops).

## Technical Details

- New migration: `ALTER TABLE trades ADD COLUMN high_water_mark NUMERIC(20,8) NULL;` Defaults to `NULL`; the manager initialises it to `MAX(entry_price, current_price)` on first update.
- Broker support:
  - Alpaca: `PATCH /v2/orders/{order_id}` for replace, or cancel + submit if replace is unavailable. Verify in code.
  - IBKR: STOP order replace pattern exists in the codebase already (for ORB brackets) — can crib.
- `atr_multiple` config: under `risk.trailing_stop` block. Default 1.5 ATR. Must be tunable per strategy.
- Coordination with the static stop_loss already on the trade row: `new_stop = max(initial_stop, high_water_mark × (1 − atr_multiple))` — never widens, never below the original stop.
- Scheduler: reuse the portfolio poller's tick (`internal/portfolio/poller.go`) or run a dedicated goroutine. Pick whichever creates the least new infrastructure.
