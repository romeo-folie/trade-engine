# Task: Pyramiding into winners (DeepSeek lesson)

## Description

DeepSeek's edge in Alpha Arena was "buy on pullback, increase on breakout" — explicit pyramiding into winners. The current engine treats every signal as a fresh entry, blocked by the position-ownership check or capped by `max_open_positions`. With Epic A's `max_per_ticker` cap (default 2) in place, deliberate pyramiding becomes safe.

If a long is up X% (configurable) and the analyst returns BUY again on the same ticker, add to the position with a tightened stop instead of rejecting the duplicate.

**Hard dependency: Epic A task 002 (`max_per_ticker`) must be live in production before this lands.**

## Acceptance Criteria

- [ ] When a BUY signal fires for a ticker with an existing open long that is up ≥ `pyramid_min_gain_pct` (default `5.0%`):
  - The signal is not rejected as a duplicate position.
  - A new trade row is created (counts toward `max_per_ticker`).
  - The new trade's stop_loss is set to `max(existing_avg_entry, broker_breakeven)` so the combined position is at worst breakeven on the original.
- [ ] Subject to `risk.max_per_ticker` (Epic A task 002). At cap, the gate blocks naturally.
- [ ] Subject to `risk.max_dollar_risk_pct` (Epic B task 004) computed on the new lot only.
- [ ] Block reason `pyramid_disabled` when `risk.pyramid_enabled` is false (default `false` initially — safe rollout).
- [ ] Tests: existing-long-up-6%-and-BUY enters a second lot; existing-long-flat-and-BUY rejects; cap reached blocks.

## Technical Details

- Engine signal handler currently has a "do you already hold this ticker?" check somewhere in the BUY path — find it (memory `project_sell_position_guard_pr306` is the SELL-side equivalent; BUY-side may have a similar check).
- New config block:
  ```yaml
  risk:
    pyramid_enabled: false
    pyramid_min_gain_pct: 5.0
  ```
- Tightened stop: at minimum, ensure the combined cost basis isn't underwater when the new stop hits. Compute as `max(prev_canonical_stop, weighted_avg_entry)`.
- Update the broker's stop order on the existing position when a pyramid fires (overlap with task 006 trailing-stop manager — coordinate; the trailing manager may already be doing this).

## Dependencies

- Optionally Epic B task 006 (trailing stop manager) — pyramiding's stop-tightening may piggyback on the trailing manager's order-replace logic.
