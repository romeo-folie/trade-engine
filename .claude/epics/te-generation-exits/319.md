# Task: SELL ownership short-circuit

## Description

Today, SELL signals on tickers we don't hold pass through the LLM, get blocked at the position-ownership gate, and clutter the dashboard. Of the last 6 weeks of blocked signals, ~20% are this pattern. Two improvements:

1. **Reorder gates:** `checkPositionOwnership` should run before `checkConfidence` and `checkRiskReward` for SELL signals. The block reason is more useful and the dashboard reads cleaner.
2. **Short-circuit before the LLM call:** when a SELL strategy is being evaluated for a ticker we don't hold long, skip the LLM call entirely. The current SELL ownership guard from PR #306 is a runtime check; this task pushes the same logic to before the analyst is invoked.

## Acceptance Criteria

- [ ] `risk.CheckAll` orders ownership check first when `Action == "SELL"`.
- [ ] Engine: before invoking the analyst for a SELL strategy, query `holds_long` for the ticker. If false, log `analysis skipped — no position` and skip the LLM call entirely. Block reason persisted as `no_position` (consistent with PR #306).
- [ ] Token usage on SELL strategies for non-held tickers drops to zero (verifiable via cost-tracking logs).
- [ ] Existing SELL ownership tests still pass; new test covers the pre-LLM short-circuit.

## Technical Details

- Existing guard: `internal/risk/manager.go:checkPositionOwnership` (added in PR #306).
- Pre-LLM short-circuit lives in `internal/engine/engine.go` — the analyzer-invocation path. Need to thread strategy direction through.
- A SELL strategy is defined as: any strategy that emits SELL as its primary action. Confirm the canonical list before short-circuiting (some strategies might emit BUY *or* SELL depending on context — only short-circuit when SELL is the only or primary direction).
