# Task: Observability — counterfactual logging + daily summary counters

## Description

Without measurement, every future "should we lower the floor?" debate is unmoored. Two changes:

1. **Counterfactual logging:** for every blocked signal, also evaluate against looser thresholds (R:R 1.30 / conf 0.55) and log "would_have_passed=true" plus the reason that flipped. After two weeks we know empirically whether the gate is over- or under-tuned.
2. **Daily summary counters:** per-day rollup of signals generated, blocked-by-reason (top-N), executed, executed→winning. Surfaced in canvas dashboard. Today the only way to see this is by querying the DB directly.

## Acceptance Criteria

- [ ] When a signal is blocked, the engine also runs `risk.CheckAll` against a fixed loose-config (R:R 1.30, conf 0.55, all other gates as default) and logs:
  ```
  level=INFO msg="signal blocked counterfactual" ticker=X passed_strict=false passed_loose=true flipped_check=risk_reward_ratio
  ```
- [ ] Counterfactual evaluation skipped if the signal is blocked by a non-calibratable check (`max_open_positions`, `position_ownership`, `daily_loss_limit`, `max_drawdown`, `cooldown_after_loss`) — only the calibratable gates (confidence, R:R) are counterfactually relaxed.
- [ ] Daily-summary table (or extension of `daily_summaries`) records:
  - `signals_total`, `signals_blocked`, `signals_executed`
  - `blocked_by_reason JSONB` — keys = block_reason, values = count
  - `executed_winning`, `executed_losing` (close-time aggregation)
- [ ] Canvas dashboard surfaces the latest day's counters in a card (small, secondary placement is fine).
- [ ] API endpoint `GET /api/portfolio/daily-counters?days=N` returns the last N days of rollup.

## Technical Details

- Counterfactual evaluation lives next to the existing `risk.CheckAll` call site in `internal/engine/engine.go`.
- Daily summary writer: extend whatever job already populates `daily_summaries` (memory `project_orb_readable_outcomes_pr297` mentions related infra). If no rollup job exists yet, add one — runs once per day after market close.
- Frontend: small additional card in the canvas dashboard. Reuse existing patterns (likely a sibling of the portfolio card).

## Dependencies
