# Task: Contract identity foundation

## Description

Teach the ORB data model to identify an option contract. Today everything keys on a bare `ticker` string with a ×1 share multiplier; an option is `(underlying, expiry, strike, right)` with a ×100 multiplier. This is the foundational task — Tasks 2 (integration), 5, 6, 7, and 9 all depend on it. Follow the `018_forex_orb` precedent, which added `asset_class`+`conid` the same way.

## Acceptance Criteria
- [ ] New forward+down migration adds to `orb_trades` and `orb_sessions`: `asset_class TEXT DEFAULT 'equity'` (values: equity | option), `underlying TEXT`, `expiry DATE`, `strike NUMERIC`, `right TEXT` (C/P), `occ_symbol TEXT`, `multiplier INT DEFAULT 1`.
- [ ] `store.ORBTrade` (`internal/store/orb.go`) gains the corresponding fields; `CreateORBTrade` and reads round-trip them.
- [ ] A shared `OptionContract` value type is added and threaded (optionally, nil for non-options) through `OrderRequest`, `Position`, and `BracketParams` (`internal/execution/executor.go`, `internal/orb/executor.go`).
- [ ] All P&L / value math on the options path multiplies by `multiplier` (×100); `orb_trades.qty` semantics documented as whole contracts on the options path.
- [ ] Existing equity/forex/futures rows read back with `asset_class='equity'`/`multiplier=1` — zero behavior change on non-options paths.
- [ ] Unit tests: round-trip an option `ORBTrade`; multiplier-aware P&L computation.

## Technical Details
- Precedent to mirror: `migrations/018_forex_orb.up.sql` (`asset_class` + `conid`).
- `ORBTrade` struct: `internal/store/orb.go:26-65` (`Ticker`, `Qty int`, no contract fields today).
- Structs to extend: `OrderRequest` (`internal/execution/executor.go:36-54`), `Position` (`:92-100`), `BracketParams` (`internal/orb/executor.go:22-30`).
- Keep `OptionContract` optional/pointer so all existing call sites compile unchanged.
- OCC symbol is the canonical broker key (21-char); store it explicitly rather than re-deriving.
