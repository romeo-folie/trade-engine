# Task: Config, TUI & observability

## Description

The control surface and visibility for options-ORB. Add the config that turns it on per underlying and tunes the gates, surface option trades in the TUI with contract identity and multiplier-correct P&L, and make every gate decision observable. All default-off so merging changes nothing until explicitly enabled.

## Acceptance Criteria
- [ ] Config (`internal/config`): per-underlying options-mode opt-in (default off); gate thresholds (IV-Rank ceiling, delta band, spread ceiling, DTE cap); earnings-blackout window; premium budget + per-trade max-loss cap; time-exit window; OPRA feed selector + secret. Safe defaults; passes the config-drift guard test (`#394`) and is added to `config.example.yaml`.
- [ ] Initial universe wired as config: SPY + QQQ enabled first; NVDA + TSLA present but gated by the earnings-blackout rule.
- [ ] TUI surfaces option trades in the positions/trades views with underlying, strike, expiry, C/P, and multiplier-correct P&L; no misrendering of non-options rows.
- [ ] Observability: every gate evaluation (pass + abort) logged with inputs, values, and deciding gate (feeds the Task 3 structured result). Aborts are greppable by gate.
- [ ] Docs: a short README for options-mode config + the OPRA prerequisite.

## Technical Details
- Config precedent + drift guard: `#394` (guard walks yaml tags incl. inline embeds); remember the engine reads `~/.tradeengine/config.yaml`, not the repo copy.
- TUI: existing positions/trades views (`internal/tui`); reuse the dir-pill / P&L color patterns; contract identity from Task 1's fields.
- Keep the config additive and default-off so non-options operation is untouched (zero-regression requirement).

## Dependencies
- Task 1 (identity — TUI reads contract fields). Config scaffolding can start early.
