# Task: IV-Rank pipeline

## Description

Produce the IV-Rank value the Task 3 gate consumes, resolving the cold-start-vs-fail-closed conflict. Because the IV-Rank gate is fail-closed, an uncomputable IV series would abort every trade forever. Fix: derive a bounded window up front so the gate has a real value on day one, then grow the series forward, then extend toward a full trailing year in parallel.

## Acceptance Criteria
- [ ] **Bounded up-front derivation**: for each configured underlying, pull ~60–90 trading days of Alpaca historical option quotes (post-Feb-2024) + underlying, compute per-day near-ATM IV via Black-Scholes, and build a daily IV series.
- [ ] **Daily live-chain snapshot job**: append today's ATM IV from the live chain to the series (grows history forward from go-live).
- [ ] **IV-Rank computation**: current IV ranked within its own trailing-window min/max (window configurable; starts at the bounded seed length, extensible to 252 days).
- [ ] **IVRankProvider interface** implemented for Task 3; returns "unavailable" (never a spurious value) when the series is too short so the fail-closed gate aborts correctly.
- [ ] Parallel extension path documented/stubbed to lengthen the derived history toward a full trailing year without blocking.
- [ ] Black-Scholes IV solver unit-tested against known-value fixtures; ATM interpolation tested.
- [ ] IV series persisted (store table or KV) so restarts don't lose accrued history.

## Technical Details
- New files in `internal/options` (coordinate package scaffolding with Task 3).
- Historical data via Task 2's data client (historical quotes endpoint); underlying prices from existing candle store.
- BS inputs: option mid, underlying, strike, DTE, risk-free rate, dividend (document assumptions).
- Alpaca ships example notebooks deriving greeks/IV this way — mirror the method, not the code.
- Rate limits: full-chain daily snapshots may need the Algo Trader Plus tier (10k/min vs 200/min) — coordinate with Task 9 config / OPRA provisioning.

## Dependencies
