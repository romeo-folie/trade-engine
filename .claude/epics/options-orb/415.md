# Task: App-managed exits

## Description

Manage option exits in the app, because Alpaca offers no bracket/OCO on options. The exit triggers read the **underlying** (the feed ORB already streams), and the action is a market-close on the **option**. Reuse the dual-sided forex OCO / `StopOrderSimulator` machinery (PR #283). Add the IV-crush time exit and the mandatory end-of-session flatten.

## Acceptance Criteria
- [ ] Underlying-trigger close: watch the underlying against the trade's stored ORB stop and target; on a stop cross OR target cross, market-close the option.
- [ ] IV-crush time exit: close the position if it is not profitable within the configured number of minutes.
- [ ] End-of-session flatten: any option still open before market close is flattened — no overnight hold, no assignment exposure. This is a hard invariant, verified.
- [ ] App-managed OCO semantics: whichever exit fires first supersedes the others; no orphaned working orders remain.
- [ ] Exit fills are recorded to the trade row (exit price, reason: stop | target | time | eod) with multiplier-correct realized P&L.
- [ ] Tests: stop-cross close, target-cross close, time-exit close, EOD flatten, and "only one exit fires" OCO behavior.

## Technical Details
- Reuse pattern: forex app-managed OCO + `StopOrderSimulator` (PR #283) in `internal/execution/`.
- The underlying feed is already streamed by the ORB engine for breakout detection — subscribe the exit watcher to the same source; no new market-data path.
- Exit action uses Task 2's option order path (market close on the OCC symbol).
- Coordinate file ownership with Task 5 (both touch the options execution path) — sequential (`depends_on: [5]`), so no true parallel conflict.

## Dependencies
- Task 1 (identity), Task 5 (a live option position to manage).
