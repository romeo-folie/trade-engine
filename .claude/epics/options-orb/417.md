# Task: Backtest path

## Description

Give options-ORB a backtest twin, matching the ORB roadmap's "parity is per-guard" discipline. Replay the SAME gate functions from Task 3 against Alpaca historical option quotes (post-Feb-2024), using BS-derived IV/delta from Task 4, so a backtested accept/abort decision is provably identical to the live one on the same inputs.

## Acceptance Criteria
- [ ] An orbreplay options variant replays historical breakouts on the configured underlyings and, at each signal, runs the live Task 3 gate pipeline against a historical chain reconstructed from Alpaca historical quotes.
- [ ] IV/delta at backtest time come from Task 4's BS derivation (no historical greeks exist at Alpaca).
- [ ] Models option entry at mid and the <5% spread gate from historical bid/ask; models exits (underlying stop/target, time exit) against historical underlying candles.
- [ ] **Parity test**: given identical chain inputs, the backtest gate decision equals the live gate decision (accept/abort + chosen contract) — a direct assertion, not a re-implementation.
- [ ] Reports per-trade and aggregate results (win rate, P&L with multiplier, gate-abort counts by gate).
- [ ] Honest about coverage limits: log the Feb-2024 history floor and any names/dates with insufficient data (no silent truncation).

## Technical Details
- Extend `internal/backtest/orbreplay` (reuses live rule fns — same philosophy as PR #361).
- Reuse Task 3 gate functions directly (do not fork them) — this is what makes parity a test, not a hope.
- Historical quotes via Task 2's data client; underlying candles from existing store.
- BS derivation shared with Task 4 (same solver).

## Dependencies
- Task 3 (gate functions to mirror), Task 4 (BS/IV derivation).
